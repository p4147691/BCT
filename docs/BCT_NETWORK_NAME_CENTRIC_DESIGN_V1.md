# BCT Network Get/Set — 대화망 이름 중심 확정 설계 V1 (2026-10-31)

## 상태
- 사용자 확정 설계를 기존 격리 Worktree에 기록한다. 구현·테스트·main/LIVE 적용 완료를 의미하지 않는다.
- Run Check → Run Plan → Network Get → 실제 상태 확인 → 매니저 판단 → 필요한 경우 Network Set → Network Get 재조회 → 연결 상태 확인 → Task Run.
- Monitor는 UI일 뿐이며 실행 여부와 관계없이 BCT Core가 정본 DB를 관리한다. Monitor 우클릭과 MCP Network Set은 같은 Core 기능을 사용해야 한다.
- 기존 DB, 대화 등록, 표시 N번호, 참여 관계, 역할 태그, Work/Operation 영수증을 재사용하고 중복 저장소를 만들지 않는다. node-sync 및 PR #381은 보존한다.

## 데이터 소유권
- 노드(대화) 독립 정보: 대화 UUID, 표시번호, 창·탭 관측, 독립 메모·담당 작업 등 실제 존재하는 필드는 해당 정본에서 관리한다. 대화망에 참여하지 않아도 독립 정보는 유지한다. 메모·담당 작업의 정확한 정본 및 Monitor UI 저장 경로는 구현 전 조사한다.
- 대화망: 사용자가 입력하는 이름이 참여·검색의 기준이다. 내부 안정 ID는 첫 생성 시 자동 발급되며 사용자 입력을 요구하지 않는다.
- 소속 관계: 노드는 내부 대화망 ID를 참조한다. 대화망 이름은 정본 대화망 레코드에서 읽어 표시한다. 노드마다 이름을 별도 복제하지 않는다.
- 역할: 대화망 내 역할 태그를 소속 관계와 연결한다. 역할 태그 자체는 BCT 실행 권한을 부여하지 않는다.

## 이름 중심 변경 계약
1. 노드에 대화망 이름을 입력: 이름 정규화 후 기존 동일 이름의 대화망이 있으면 그 ID로 참여한다. 없으면 새 대화망 및 ID를 생성하고 참여한다. 조회-생성-참여는 동시성·중복 방지 하에 원자적으로 처리한다.
2. 이름을 비움: 해당 노드의 활성 대화망 소속을 해제하고 화면상 이름·ID를 표시하지 않는다. 독립 노드 기록과 과거 참여 이력은 보존한다.
3. 일부 노드의 대화망 이름을 바꿈: 해당 노드만 기존/신규 대화망으로 이동한다. 다른 노드는 변경하지 않는다.
4. 대화망 전체 이름 변경: 기존 내부 ID 및 모든 참여 관계를 유지하고 정본 이름만 바꾼다. 모든 소속 노드 화면은 새 이름을 반영한다.
5. 기존 이름과 충돌: 다른 대화망의 이름과 중복되면 임의 병합하지 않고 충돌을 반환한다. 병합은 별도 명시적 결정이 필요하다.
6. 마지막 노드가 나감: 활성 참여자가 0이어도 대화망의 과거 기록과 내부 ID는 보존한다. 신규 이름 입력 시 보존된 이름과의 재사용/재활성 정책은 기존 DB 계약과 대조해 확정한다.
7. 사용자가 입력한 이름은 편의 식별자이며 UUID/내부 ID를 수동으로 관리할 필요가 없다.

## Get/Set 명칭
- 공개 사용자 경로는 Network Get / Network Set으로 통일한다. 내부 project-upsert, membership-assign, role-patch는 기존 구현과의 호환을 유지하되 사용자에게 별도 공개 명령처럼 설명하지 않는다.
- Network Get은 정본 대화망·소속·역할을 읽고 필요하면 기존 상태 조회와 연결한다. 실제 연결·세션·RCC 상태는 기존 조회 기능으로 확인하며 별도 중복 상태 저장소를 만들지 않는다.
- Network Set은 실제 구성 변경이 필요할 때만 호출한다. 변경 후 Get으로 의도와 일치하는지 검증한다.
- 새 ChatGPT 창·탭 생성 및 이동·정리는 Network Set의 DB 갱신과 별도이다. 필요 시 기존 RCC/브라우저 생성 명령을 호출하며 창 정리는 추후 설계한다.

## 구현 전 필수 대조
- Monitor 우클릭 노드 정보 편집의 실제 저장 함수·정본 경로를 확인한다. 동일 경로가 아니라면 공통 Core API로 정리하되 기존 화면 동작을 보존한다.
- 기존 conversation_network_projects / conversations / memberships / membership_tags / node_labels의 실제 의미와 제약을 확인한다.
- 이름 정규화, 기존 이름 중복, 미소속 전환, 부분 이동, 전체 이름 변경, 마지막 멤버 탈퇴, 동시 편집, 기존 기록 보존을 격리 시험한다.
- 변경 소유권과 영향 범위를 확인한 후 격리 PR·CI·보호된 배포·E2E를 수행한다. 이 문서 작성만으로 LIVE 적용을 주장하지 않는다.
