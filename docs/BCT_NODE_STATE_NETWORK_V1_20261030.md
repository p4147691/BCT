# BCT Node State / 대화망 정보 구조 V1 (2026-10-30)

## 목적
Monitor에서 관측한 **현재 실제 존재하는 노드**에 사람이 지정한 대화망/프로젝트/역할/메모를 연결하고, 새 작업 지시 시 최신 정보를 함께 전달한다. 별도의 중복 관리표나 권한 부여용 대화망을 만들지 않는다.

## 전역 감독관
- BCT 전체의 감독관 역할은 **하나**이며, 개별 대화망의 구성원이 아니다.
- main 병합·정확한 LIVE 배포·E2E 책임은 전역 감독관이 담당한다.
- 자유 입력 역할 태그에 '감독관'이 포함되어도 실제 병합·배포 권한이 자동 부여되지 않는다.

## 사용자용 상태 이름 (아직 신규 API 아님)
- `bct-state`: 전체 서비스/작업/연결/영수증 현황. 기존 `bct_status` 활용.
- `node-state`: **현재 관측된 실제 노드만** 번호·대화창 이름·활동·소속 대화망·역할·담당 작업과 함께 투영. 기존 `current_nodes` + 등록된 대화망 메타데이터 결합.
- `rcc-state`: RCC 연결 인스턴스·세션·창/탭/대화 UUID. 기존 RCC `state`.
- `monitor-state`: 창/탭 위치·활동·표시 등 실제 Monitor 관측. 없는 정보는 미확인으로 표시.
- `node-update`: 노드의 사람이 편집하는 이름·역할·소속·메모. 기존 `bct_conversation_network_update` 계약과 Monitor 우클릭 편집 경로를 정합화할 후보.
- `network-update`: 대화망 이름·목표·구성원/역할 갱신. 기존 대화망 업데이트 계약 재사용.
- 이 이름은 설명용 별칭이며 현재 공개 MCP 명령을 대체하거나 새 호출로 가장하지 않는다.

## 존재/이력 경계
- Chrome 탭/대화가 닫히면 현재 `node-state`에서 **사라진다**. '닫힘 노드'라는 현재 상태를 만들지 않는다.
- 등록된 과거 대화/영속 Work·영수증·이력은 별도 이력으로 보존할 수 있다. 이를 현재 노드 수에 합산하지 않는다.
- 노드 번호/Monitor 라벨은 사람이 읽는 별칭이다. 정확한 전송 대상은 RCC가 확인한 세션·탭·대화 UUID로 지정한다.

## 관측과 관리
- 동일 노드/대화망의 **하나의 논리적 정보**를 조회/편집한다. 관측값과 편집값을 서로 다른 테이블로 중복 복제하지 않는다.
- 관측값은 RCC/Monitor가 제공한 사실·관측시각·출처를 유지한다. 편집값은 사용자/매니저가 지정한 이름·역할·소속·설명이다.
- 매니저는 대화망에 소속된 작업자 선택·역할 수정·지시문 구성에 관여하지만 역할 태그는 자율 협업용 안내이며 실행 권한을 부여하지 않는다.
- 대화망은 협업 관계에 대한 **정보 기록**이다. 다른 노드의 통제권·메시지 전송 권한·작업 소유권을 자동 획득시키는 강제 경계가 아니다.

## 새 작업 지시 흐름
1. `bct_status/current_nodes`·대화망 등록 정보·RCC `state`에서 실제 현재 노드와 역할/소속을 확인한다.
2. 현재 이용 가능한 노드를 우선 선택하고 없을 때만 `create-chat-tab` 또는 `create-chat-window`로 새 노드를 만든다.
3. `compose_worker_delivery`로 대화망 이름·목표·현재 구성원/역할·이번 작업·완료 기준·보고 대상을 구성한다.
4. `send-message`로 정확한 대상에 제출한다. BCT Operation 영수증, RCC 결과, 해당 턴 응답을 구분한다.
5. `node-sync`, Inbox, 오케스트레이션 영속 경로를 기존 계약으로 유지한다. 사용자용 API가 복잡한 내부 단계를 노출하지 않도록 한다.

## 구현 전 검증
- Monitor 우클릭 편집 정보와 BCT 대화망 메타데이터의 실제 저장/동기화 경로 확인.
- 닫힌 탭이 current_nodes에 남지 않는지, 이력은 보존되는지 테스트.
- 전역 감독관과 개별 대화망 매니저 역할의 권한/표시 분리.
- 첫 접촉 메시지의 정보 정확성·길이·응답 회수 검증.
- 기존 Core/RCC/Monitor/Browser Bridge의 운영 동작은 이 문서 작업으로 변경하지 않는다.

## 상태 조회 명칭 V1 (2026-10-30 확정)
- 사용자 표현: `status bct`, `status node`, `status rcc`, `status monitor`.
- 실제 단일 MCP 도구: `bct_status(scope="bct"|"node"|"rcc"|"monitor")`. 기존 `bct_status()` 호출은 이전 전체 응답을 그대로 유지한다.
- `status bct`: 기존 Core/Monitor 전체 응답. MCP/터널 정보가 확인되지 않으면 임의로 정상으로 채우지 않는다.
- `status node`: `current_nodes`의 현재 실제 노드만. 등록 이력의 닫힌 노드는 포함하지 않는다. 역할/소속/메모는 Monitor 우클릭 데이터와 BCT 정본의 실제 연결이 검증되기 전에는 임의로 병합하지 않는다.
- `status rcc`: 현재 RCC 관측 스냅샷.
- `status monitor`: 현재 Monitor 서비스·관측·노드 표시 투영. 화면 픽셀/썸네일 원본을 이 명령이 가져온다고 주장하지 않는다.
- 노드 정보는 하나의 논리적 객체이며 번호순/대화망별/역할별/활동순 정렬은 **같은 정보의 보기 방식**이다. 정렬이나 필터로 새 노드·소속·권한을 만들지 않는다.
- `create-chat-tab`, `create-chat-window`, `send-message`는 이름과 계약을 변경하지 않는다.
