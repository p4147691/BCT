# Loop Recipe 조립 카드

이 카드만 보면 됩니다. Watch, 전송, 영수증, 재시작 복구의 내부 구현은
블록을 조립하는 사람이 알 필요가 없습니다.

## 블록 하나를 만들 때 쓰는 양식

```text
블록 이름:
이 블록이 하는 일:
입력으로 필요한 것:
끝났을 때 남기는 결과:

결과가 좋으면:      CONTINUE → 다음 블록 이름
기다려야 하면:      WAIT
다른 담당이 필요하면: HANDOFF
완료되면:           COMPLETE
문제가 생기면:      BLOCKED
```

## 다섯 가지 선택

| 선택 | 뜻 | 내부에서 시스템이 하는 일 |
|---|---|---|
| `CONTINUE` | 바로 다음 일을 한다 | 조립표의 다음 블록으로 이동 |
| `WAIT` | 답변·시간·외부 결과를 기다린다 | Watch 등록, 재시작 뒤 재개, Wake 처리 |
| `HANDOFF` | 다른 담당에게 넘긴다 | 대상 선택, 신원 확인, Watch, 전달, 영수증 기록 |
| `COMPLETE` | 이 Loop를 끝낸다 | 완료 기록과 결과 정리 |
| `BLOCKED` | 지금은 안전하게 진행할 수 없다 | 원 영수증 확인, 보류, 복구/승인 경로 |

## 가장 흔한 조립

```text
[계획]
  └─ CONTINUE → [실행]

[실행]
  └─ CONTINUE → [평가]

[평가]
  ├─ COMPLETE → [완료]
  ├─ CONTINUE → [계획]
  ├─ HANDOFF  → [계획]
  └─ BLOCKED  → [복구]
```

`HANDOFF → [계획]`은 같은 A가 다시 계획을 만들 수도 있고, 다른 endpoint가
계획을 만들 수도 있습니다. 어느 쪽인지는 Loop의 조립표와 endpoint 설정이
정하며, 이 블록 카드에는 적지 않습니다.

## 기억할 것은 한 문장

```text
블록은 일을 하고, 다섯 가지 중 하나로 끝낸다.
```

그 밖의 연결, 전달, Watch, 영수증, UNKNOWN 무재전송, 재시작 복구는 범용
전달선이 책임집니다.

Supervisor가 없으면 처리 블록을 바꾸지 않습니다. Loop의 연결 준비 단계가
`prepare_supervisor`로 새 대화를 만들고 첫 역할 지시를 보낸 뒤, 그 생성·전송
영수증에 결속된 bootstrap Watch와 Node Info를 기록합니다. 새 대화 UUID는 첫
전송 전에는 존재하지 않으므로 이 준비 단계만 `생성 → 첫 전송 → 영수증 검증
Watch` 순서를 사용합니다. UNKNOWN이면 같은 Operation 영수증만 확인하며 새
대화나 메시지를 다시 만들지 않습니다.

## 새 기능을 넣고 싶을 때

- 새로운 일을 한다면: 새 블록을 하나 추가합니다.
- 기존 일 다음에 한 단계를 더 넣는다면: `CONTINUE`의 다음 블록만 바꿉니다.
- 다른 담당이 해야 한다면: `HANDOFF`를 고릅니다.
- 답을 기다려야 한다면: `WAIT`를 고릅니다.
- 안전하지 않으면: `BLOCKED`를 고릅니다.

새로운 전송 방식이나 외부 시스템을 처음 연결할 때만 개발자가 범용 전달선에
adapter를 한 번 추가합니다. 이후 블록 작성자는 그 adapter를 알 필요가 없습니다.
