# BCT Run Plan — 확정 설계 V2 (2026-10-31)

## 상태 및 범위
- 사용자 확정 설계. 이 문서는 실행 계약의 목표이며 구현·LIVE 적용을 뜻하지 않는다.
- 기존 Run Check V3, ProjectContextJStore, Work/Operation 영수증, node-sync를 재사용한다. 별도 AI 판단 엔진·중복 DB·채팅 원문 저장소를 만들지 않는다.
- 기존 PR #381과 Chrome/RCC/Monitor는 이 설계 반영의 변경 대상이 아니다.

## 기본 흐름
1. Run Check: 현재 매니저의 실제 노드·대화망 소속, 프로젝트 ID/제목, 저장된 공통 요약과 필요 시 상세 맥락·Work 기록을 조회한다. ID/제목 일치만으로 동일 작업을 확정하지 않는다.
2. 현실 대조: 현재 Work/Operation 영수증과 필요한 소스·테스트·GitHub·LIVE·실행 상태를 확인한다. 오래된 요약이나 불명확한 관측은 사실로 단정하지 않는다.
3. 매니저 AI 판단: 기존 계획 재개 / 같은 프로젝트의 새 계획 / 새 프로젝트와 계획을 구분한다. 명확하면 자율 결정하고 중요한 불확실성이 남으면 사용자에게 구체적으로 질문한다.
4. Run Plan: 매니저 AI가 목표, 전체 완료 조건, 단계별 완료 조건, 확인되지 않은 가정, 허용 재량 및 판단 근거를 작성한다. BCT는 유효성·권한·버전·중복을 검증하고 저장한다.
5. 필요할 때만 Network Get/Set으로 기존 대화망을 재사용·조정하고, 실제 실행 전에 세션·attachment 및 권한을 재검증한다. 이후 Task Run/Chain Run으로 진행한다.

## 항목별 확정 규칙
- plan_id: 새 계획을 만들 때 매니저/호출 경로가 유일한 ID를 준비한다. 기존 계획 수정은 동일 ID를 재사용한다. 사용자가 직접 입력하지 않는다. 현재 API는 plan_id를 필수 입력으로 받으므로 자동 발급 구현 완료로 오해하지 않는다.
- project: Run Check에서 찾은 프로젝트를 상세 검증해 재사용한다. 일치하는 것이 없으면 기존 권한 절차에 따라 신규 프로젝트를 만든다. 현재 Run Plan 자체가 프로젝트를 자동 생성하지는 않는다.
- objective: 사용자의 지시·확인된 맥락을 바탕으로 AI가 작성한다.
- acceptance: 결과·증거·검증 방법을 식별할 수 있는 명확한 완료 조건으로 AI가 작성한다. 작업 성격과 무관한 CI/LIVE를 무조건 강제하지 않는다.
- steps: AI가 실행 순서와 각 단계별 완료 조건을 작성한다. 이미 완료된 외부 효과는 영수증 확인 없이 반복하지 않는다.
- assumptions: 확인되지 않은 전제만 표시하고 확인된 사실과 구별한다.
- discretion: 세부 구현 방법·순서·안전한 조사/격리 테스트는 허용된 Work 범위에서 자율 판단한다. 재량은 BCT 권한이나 보호 승인 절차를 확대하지 않는다.
- expected_revision: BCT 저장소의 충돌 방지용 버전이다. 수정 전에 최신 버전을 확인하고, 일치하지 않으면 재조회·차이 대조 후 결정한다. 사용자가 관리하지 않는다.
- author: 기록용 메타데이터만 남긴다. 매니저 이름·노드 번호·창 번호·UUID 중 하나를 사용자에게 요구하지 않는다. author 문자열을 인증·권한·계획 승계·프로젝트 일치 판정에 사용하지 않는다. 신뢰된 Work·Operation 영수증이 권한과 변경 이력의 근거다. 현재 API는 author 문자열을 필수로 받으므로 호출 측에서 준비한다.

## 재개/신규 계획 판단
- 기존 목표·범위·실제 진행 상태가 명확히 연속되면 기존 계획을 이어받는다. 저장된 완료 표시와 실제 영수증·현실이 충돌하면 사실 확인을 먼저 한다.
- 같은 프로젝트라도 목표가 독립적이면 새 계획과 필요한 Work를 분리한다.
- 관련 프로젝트 후보가 여러 개여도 추가 상세 조회로 구분 가능하면 AI가 판단한다.
- 중요한 방향 변경, 상충하는 후보 중 선택, 기존 데이터 대체 등에서 검증으로도 해소되지 않는 중요한 불확실성은 사용자에게 질문한다. 불확실한 부분만 보류하고 독립적인 안전 작업은 계속한다.
- 기존 계획을 수정하면 변경 이유와 이전 버전 근거를 남긴다. 원본 영수증·UNKNOWN/Claim 기록은 보존한다.

## 구현·검증 시 확인할 차이
- 현재 bct_run_plan은 plan_id, project, objective, acceptance, steps, author를 호출자가 전달하고 expected_revision을 검증한다. AI가 계획을 작성한다는 것은 호출자 측 절차이며 별도 계획 엔진이 아니다.
- 자동 ID 부여, 현재 상태와의 대조, 중요 질문 분기, 작성자 자동 기록, 기존 계획 이어받기 판단은 이 문서의 운영 설계이며 현재 명령 자체의 구현 완료를 뜻하지 않는다.
- 추후 구현 전에는 기존 Work 소유권·지침 정합성·영향 회귀를 검증하고 독립 PR/CI 및 보호된 배포 절차를 따른다.
