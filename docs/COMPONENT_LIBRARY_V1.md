# BCT Component Library V1

이 문서는 BCT에서 재사용 가능한 기능을 찾는 **책꽂이의 사용 설명서**다.
기계가 읽는 정본 목록은 `docs/component-library.v1.json`이다. 목록은 현재
검증된 핵심 경계부터 넣는 curated 목록이며, 저장소 전체를 완전하게 열거했다고
주장하지 않는다.

## 네 종류

1. `primitive` — 더 나누면 안전 계약이 깨지는 한 번의 읽기·효과·원자 상태 전환
2. `module` — 안정된 입력과 결과를 가진 재사용 기능
3. `partial_recipe` — 여러 부품을 순서대로 조립하지만 중간에 AI나 상위 흐름의 판단이 필요한 조합
4. `full_recipe` — 시작·완료·복구 경계까지 가진 사용자 단위 흐름

`kind`와 별도로 `maturity`를 둔다. 큰 파일 속 함수라도 계약은 재사용할 수 있지만
`embedded`로 표시한다. 독립 파일과 집중 검사가 생기면 `isolated`로 승격한다.
따라서 이름만 부품인 코드와 실제로 꺼내 쓸 수 있는 부품을 구분할 수 있다.

## 새 기능을 만들 때

1. 먼저 목록에서 같은 효과·영수증·안전 규칙을 가진 부품을 찾는다.
2. 있으면 새로 복사하지 않고 그 부품을 호출한다.
3. 없으면 가장 작은 계약으로 구현하고 집중 검사를 붙인다.
4. 여러 부품을 연결하는 순서와 AI 판단 지점은 레시피로 따로 기록한다.
5. LIVE에서 검증된 사실과 소스에만 있는 후보를 같은 것으로 표시하지 않는다.

브라우저처럼 외부 효과가 있는 부품은 `NOT_APPLIED / APPLIED 또는 CLOSED / UNKNOWN`
경계를 가져야 한다. UNKNOWN은 새 ID로 재시도하지 않는다. BCT가 상태와 증거를
기록하더라도 후임 선택·계속 진행·완료 같은 판단은 AI 또는 사용자가 한다.

## 현재 창 닫기와 복구

- 실제 탭 닫기는 `browser.close_exact_chat_tab` 원시 부품으로 분리됐다.
- BCT 공개 진입점 `bct.close_tab`은 Work와 RCC 영수증을 더한 부품 모듈이다.
- 휴지통 기록 생성과 메타데이터 복구는 재사용 경계가 있지만 아직
  `desktop-lifecycle.js` 안에 있으므로 `embedded`다.
- 휴지통 삭제와 복구는 각각 부분 레시피다. 이후 작은 파일로 옮길 때에도
  JSON 목록의 ID와 계약은 유지한다.
